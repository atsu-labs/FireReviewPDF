# 開発ルール・指示書 (for AI Agent)

> [!IMPORTANT]
> `.agent/rules/development-rules.md`、`.clinerules`、`.cursorrules` は同一のコンテンツを保持しています。変更時は必ずすべてのファイルを同期して更新してください。

AIエージェントがコミットやプルリクエストを作成する際は、以下のガイドラインを必ず遵守してください。

## 1. コミットメッセージ

- コミットメッセージおよび説明文は、必ず**日本語**で記述してください。
- 1行目（件名）は50文字以内で変更内容を簡潔に要約してください。
- 必要に応じて本文に詳細を記載してください（72文字で折り返し）。
- Conventional Commits 形式（例: `feat:`, `refactor:`, `fix:`）を使用する場合も、要約・説明部分は日本語で記述してください。

### 例
```
feat: PDF プレビュー機能を追加

ページナビゲーターとプロパティパネルから
PDFファイルのプレビューができるようになった。
```

---

## 2. プルリクエスト (PR)

- PR のタイトルおよび説明文は、必ず**日本語**で記載してください。
- 説明文には以下の項目を含めてください。
  - **変更概要**: 何を変更したか
  - **変更理由**: なぜ変更が必要だったか
  - **テスト方法**: 動作確認の手順
  - **関連 Issue**: 対応する Issue 番号（マージ時に自動でクローズされるように `Closes #123` や `Fixes #123` などのキーワードを使用してください）
- PRレビューの指摘に対する返答やコメントを行う際は、挨拶や「レビューありがとうございます」といった定型的な挨拶文・不要な表現は含めず、技術的な対応内容や設計判断・結論のみを簡潔に記述してください。

---

## 3. コード・コメント

- コード内のコメントは**日本語**で記載することを推奨します。
- 変数名・関数名・クラス名は英語のままとします。
- Pythonコードは **PEP 8 スタイルガイドライン** に準拠してください。
- 新規ファイルの配置やインポートの際は、既存のディレクトリ構造（`src/firereview/`）とモジュール構成を厳格に維持してください。

---

## 4. テストの実行

- 自動テスト・ユニットテストを実行する際は、直接 `pytest` コマンドを叩くのではなく、必ず **`py -m pytest`** を使用してください。

---

## 5. ドキュメントの同期・更新

- 機能追加、UI・操作仕様の変更、アーキテクチャのリファクタリング、またはファイル・ディレクトリ構成の変更（新規モジュールやテストファイルの追加など）を行った際は、**必ずコミット・PR作成前に `README.md` などの関連ドキュメントを確認し、最新の状態に更新してください**。
  - **機能の追加・仕様変更時**: `1. 主な機能` および `3. 基本的な操作フロー` の記述を実際の挙動に合わせて更新する。
  - **依存関係・ビルド・テスト手順の変更時**: `2. セットアップと実行方法` を更新する。
  - **設計変更・ファイル追加/移動/削除時**: `4. 技術仕様（開発者向け）` のアーキテクチャ説明およびファイル構成ツリーを更新する。
